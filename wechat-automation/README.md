# 微信运营自动化

沉淀朋友圈、视频号、公众号／服务号及后续企业微信的素材处理和内容生成规则。

## 当前状态与第一阶段

本目录目前仅有说明文档，未接入微信账号或发布接口。第一阶段流程为：素材归集 → 生成文案／标题／简介／案例稿 → 待审核 → 人工确认后发布。

## 建议结构

| 路径 | 用途 |
| --- | --- |
| src/ | 素材整理及内容生成代码 |
| prompts/ | 分平台提示词和事实约束 |
| templates/ | 文案、视频简介、案例稿空白模板 |
| examples/ | 已获准公开或虚构标注清楚的示例素材与输出 |
| docs/ | 素材字段、审核步骤及运行说明 |
| tests/ | 内容字段、事实约束及待审核状态验证 |

## 素材与审核模板

- 素材编号、来源及日期：待填写。
- 项目类型、已核实事实、适用平台：待填写。
- 客户名称、照片和案例是否获准公开：待确认。
- 生成稿位置、审核人、审核状态、修改意见：待填写。
- 最终发布版本、渠道及时间：发布后登记，内部记录留本地。

真实项目优先，不虚构效果、金额、评价或客户授权。素材事实不足时列出待补问题。客户聊天记录、联系方式、原始照片和待审核内容留在受控位置；公开仓库仅保留脱敏模板。

## 迁入与验收

先迁品牌口径、提示词和空白模板，再迁素材整理与生成脚本。使用脱敏样例验证三类输出：朋友圈文案、视频标题与简介、公众号案例稿。确认事实可追溯、缺失信息被标注、输出进入待审核后才验收。

执行环境、模型服务、安装步骤及真实命令尚待核对；不编造可运行命令。账号凭证放环境变量，不提交登录状态、Cookie 或二维码。

## 维护信息模板

迁入时逐项填写，未知项保留“待确认”，不要把示例写成已实现功能。

- 负责人：待确认
- 来源位置／原项目：待确认
- 最近验证日期：待确认
- 当前版本／提交：待确认
- 依赖及版本：待确认
- 输入与输出位置：待确认
- 执行命令（含工作目录）：待确认
- 验证方法及预期结果：待确认
- 故障处理与回退方法：待确认
